DFIR — USB FORENSICS

USB forensics: registry, event logs, Shellbags and Jump Lists

A practical guide to tracking USB device usage on Windows and building a complete investigation timeline for DFIR, Insider Threat, and Data Exfiltration cases.

Topic — USBSTOR, Event Logs, Shellbags, Jump Lists Use case — DFIR, Insider Threat, Data Exfiltration Read — ~8 min

01Registry artifacts

1.1 USBSTOR — storage devices only

HKLM\SYSTEM\CurrentControlSet\Enum\USBSTOR

Covers flash drives, external HDDs/SSDs, and memory card readers. Not all USB devices — storage only.

Structure:

USBSTOR
 └── Disk&Ven_SanDisk&Prod_Cruzer_Blade    ← Vendor / Product
      └── 4C530001230101117123              ← Serial Number

Key values inside the Serial Number subkey:

ValueExamplePurpose
FriendlyNameSanDisk Cruzer Blade USB DeviceHuman-readable device name
ContainerID{d4f7a123-xxxx-xxxx-xxxx}Correlate device across Event Logs and SetupAPI
The serial number is your most important IOC — it lets you link the same drive across multiple machines and investigations.

1.2 Connection and disconnect times

Under the serial number subkey → Properties → key starting with 83da6326...:

ValueMeaning
0064First / Last connection time
0066Disconnect time

1.3 USB key — all USB devices

HKLM\SYSTEM\CurrentControlSet\Enum\USB

Covers everything: keyboards, mice, Bluetooth adapters, webcams, hubs, and storage devices. Check the Service value inside each device subkey to identify type:

Service valueDevice type
diskStorage device
BTHUSBBluetooth adapter

02USB event logs

All three sources live under:

Event Viewer → Applications and Services Logs → Microsoft → Windows

2.1 Partition / Diagnostic — Event ID 1006

Logged on USB connection. Contains:

Manufacturer = SanDisk
Model        = Cruzer Blade
Size         = 64 GB
Serial       = 4C530001230101117123

Cross-referencing this serial with USBSTOR gives you independent corroboration from two sources.

2.2 Kernel-PnP — Event IDs 400 / 410

Logged when Windows configures the device. Contains Device Name, Class GUID, and Device Instance ID. The Class GUID (e.g. {4d36e967-e325-11ce-bfc1-08002be10318}) appears in the Registry too — same GUID + same timestamp across sources = same device.

2.3 NTFS / Operational — Event ID 142

Reveals the drive letter Windows assigned:

Volume Name = E:

This is the link between the physical device and everything that follows (Shellbags, Jump Lists, file access logs).

03Shellbags

3.1 What they are

Windows stores Shellbags in the Registry to remember folder display preferences (icon size, sort order, view type). For DFIR, they become a record of user folder navigation — even after the folder or the drive is gone.

3.2 Locations

NTUSER.DAT\Software\Microsoft\Windows\Shell\BagMRU
NTUSER.DAT\Software\Microsoft\Windows\Shell\Bags
USRCLASS.DAT\Local Settings\Software\Microsoft\Windows\Shell\BagMRU
USRCLASS.DAT\Local Settings\Software\Microsoft\Windows\Shell\Bags

Shellbags are user-specific — C:\Users\Ahmed\NTUSER.DAT shows what Ahmed browsed, not another user.

Tool: Shellbag Explorer (Eric Zimmerman)

3.3 What they tell you

After identifying drive letter E: from Event ID 142, Shellbag Explorer might show:

E:
 └── Secret_Project_LD

This proves the user actively navigated into that folder — not just that the drive existed.

3.4 Key limitation

Shellbags prove folder access, not file access. For file-level proof you need Jump Lists, LNK files, or Office MRUs.

3.5 ZIP files — a lesser-known capability

Windows treats ZIPs opened in Explorer as folders. If a user browsed inside E:\Archive.zip, Shellbags records:

E:\Archive.zip
 └── Financial_Reports

This can expose the contents of an archive that was later deleted — as long as the user navigated it through Explorer.

04Jump Lists

4.1 What they are

Introduced in Windows 7, present through Windows 11. When a user opens a file with any application, Windows records it per-application. The "Recent Files" list you see when right-clicking apps on the Taskbar comes directly from Jump Lists.

4.2 Why they matter

Shellbags = folder browsed. Jump Lists = file opened. Survives drive removal, file deletion, and application uninstallation.

4.3 Locations

AutomaticDestinations: C:\Users\<User>\AppData\Roaming\Microsoft\Windows\Recent\AutomaticDestinations
CustomDestinations:    C:\Users\<User>\AppData\Roaming\Microsoft\Windows\Recent\CustomDestinations

Files are named by AppID (e.g. 9b9cdc69c1c24e2b.automaticDestinations-ms) — each ID maps to a specific application.

Tool: JumpList Explorer (Eric Zimmerman)

4.4 What they expose

From a single entry you get: full file path, application used, access timestamp, and sometimes open count.

Example: following up on the Shellbag finding (E:\Secret_Project_LD), JumpList Explorer reveals:

Path:        E:\Secret_Project_LD\Dumped_Passwords.txt
Application: Notepad.exe
Access Time: 2023-10-23 08:07:14

06Complete investigation timeline

TimeEvidence
08:05USB connected — SanDisk Cruzer Blade, serial 4C530001230101117123 (USBSTOR + Event 1006)
08:05Drive letter assigned: E: (NTFS Event 142)
08:06User browsed E:\Secret_Project_LD (Shellbags)
08:07User opened Dumped_Passwords.txt with Notepad (Jump Lists)
08:10USB removed (Registry value 0066)

This transforms the investigation conclusion from:

A USB flash drive was connected to the machine.

into:

At 08:07, the user opened Dumped_Passwords.txt from a SanDisk Cruzer Blade
(serial: 4C530001230101117123, drive E:) using Notepad — 2 minutes after connecting the drive.
That level of specificity is what DFIR, Insider Threat, and Data Exfiltration cases require.
